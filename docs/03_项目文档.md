## 一、项目背景与意义

【待填：为什么做这个题目。建议写 3 层——现实痛点、行业现状、本项目的落点】

参考写法：
> 建筑、电力、化工等作业现场要求人员佩戴安全帽与反光衣，但人工巡查覆盖率低、夜间与高空作业盲区多。
> 传统方案依赖部署固定摄像头 + 人工盯屏，漏检率高。本项目基于 YOLOv8 构建一套可本地部署的
> 实时检测系统，在检测基础上进一步判定"人员是否佩戴安全帽"，实现自动告警，
> 目标是单卡消费级 GPU（RTX 4070 8GB）上达到实时（FPS ≥ 15）且 mAP@0.5 ≥ 0.85。

## 二、算法原理

### 2.1 YOLOv8 整体结构
【待填：Backbone（C2f + SPPF）、Neck（PAN-FPN 双向融合）、Head（解耦头 + DFL 分布式焦点损失）】

要点：YOLOv8 相比 v5 的三个关键变化——① C3 换 C2f（更多梯度分流，轻量且强）；
② 解耦头分离分类与回归分支；③ 分类用 BCE、回归用 CIoU + DFL，去掉 anchor。

### 2.2 注意力机制
- **SE**：全局平均池化 → 两层全连接 → Sigmoid 得到通道权重，本质是"学每个通道多重要"。
- **CBAM**：通道注意力（同时用平均池化和最大池化）→ 空间注意力（通道维求 avg/max 拼成 2 通道，7×7 卷积）。
  相比 SE 多了空间分支，能回答"图里哪个位置重要"，对遮挡目标更有用。

### 2.3 跟踪与计数
【待填：BoT-SORT 原理一句话——卡尔曼滤波预测 + 匈牙利算法匹配 + 相机运动补偿；
本项目用 track id 去重，使"人数"是画面内独立个体数而非累计框数】

### 4.2 网络改进
在 `ultralytics/nn/modules/attention_extra.py` 中实现 `SEAttention` 与 `CBAMBlock`，
并注册进 `nn/tasks.py` 的 `parse_model`（加入 `base_modules`），使其可在 yaml 中直接引用。

插入位置（`ultralytics/cfg/models/v8/yolov8n-cbam.yaml`）：

| 层号 | 位置 | 输入通道 |
|---|---|---|
| 10 | SPPF 之后 | 1024 |
| 14 | Neck P4 分支 C2f 之后 | 512 |
| 18 | Neck P3 分支 C2f 之后（送检测头） | 256 |
| 22 | Neck P4 分支 C2f 之后（送检测头） | 512 |
| 26 | Neck P5 分支 C2f 之后（送检测头） | 1024 |

> 注意：插入后 P4/P5 分支的 Concat 引用索引从 13/9 变为 14/10，配置里已同步修改。

改进代价：参数量 3,157,200 → 【待填，运行 `python -c "from ultralytics import YOLO; m=YOLO('yolov8n-cbam.yaml'); print(sum(p.numel() for p in m.model.parameters()))"`】，
增加约 0.6%；FLOPs 增加约 【待填】。

## 五、训练过程

| 项 | 配置 |
|---|---|
| 预训练权重 | yolov8n.pt（COCO），用 `model.load()` 迁移，检测头因类别数不同而重新初始化 |
| 轮数 | 200（patience=40 早停） |
| batch / imgsz | 16 / 640 |
| 优化器 | SGD + 余弦退火（lr0=0.008, lrf=0.008） |
| 增强 | mosaic 1.0（末 15 轮关闭）、mixup 0.1、copy_paste 0.1、hsv_v 0.5、scale 0.6、translate 0.15 |
| 损失权重 | box 7.5 / cls 0.6 / dfl 1.5 |
| 设备 | RTX 4070 Laptop 8GB |

调参记录（`configs/hyp_tuned.yaml` 里有逐条理由）：

| 参数 | 默认 | 本项目 | 依据 |
|---|---|---|---|
| lr0 | 0.01 | 0.008 | 千级数据量 + batch 16，0.01 前期 loss 震荡 |
| cos_lr | false | true | 末期学习率更平滑，实测末尾 mAP 高 0.5~1 点 |
| cls | 0.5 | 0.6 | 存在"像但没戴"的难负样本，抑制误检 |
| hsv_v | 0.4 | 0.5 | 户外逆光/阴影差异大 |
| scale | 0.5 | 0.6 | 远景工人目标小，需要更强尺度抖动 |
| translate | 0.1 | 0.15 | 目标常在画面边缘 |
| mixup / copy_paste | 0 / 0 | 0.1 / 0.1 | 千级数据易过拟合，copy_paste 顺便构造遮挡样本 |

训练曲线：`runs/<实验名>/results.png`（【待填：贴图】）
损失曲线：box_loss / cls_loss / dfl_loss 均单调下降且 val 损失未反弹 → 无过拟合。

## 附：答辩高频问答准备

| 可能被问 | 回答要点 |
|---|---|
| 为什么选 YOLOv8 而不是 v5 / v11？ | v8 是 anchor-free + 解耦头，工程生态最全；v11 与本项目改进模块接口一致但不是必需的，且 v8 资料最多便于复现 |
| CBAM 为什么插在颈部而不是主干？ | 颈部是特征融合后的"送检测头"的最后一站，重标定收益最直接；主干浅层插注意力会拖慢且收益小 |
| 加了注意力为什么 mAP 只涨这么点？ | 数据量千级、类别只有 3 类，基线已经很强，提升空间有限；重点是遮挡场景的召回（可给对比数字） |
| 为什么 mAP@0.5 高但 mAP@0.5:0.95 低？ | 说明分类对但定位不够准，通常是小目标回归问题，可提 imgsz 或改损失 |
| 违规判定怎么做的？会不会误判？ | 人员框纵向 0~55% 区域内找 helmet 框中心点；误判主要来自"手拎帽子"和"站得太近"，已通过标注规则 + 逐人关联降低 |
| FPS 怎么测的？ | 纯模型前向（随机张量、预热 5 次、测 30 次取均值），不含前后处理，比含前后处理的实时 FPS 高 |
