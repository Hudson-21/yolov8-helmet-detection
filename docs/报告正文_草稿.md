## 项目名称

基于 YOLOv8 改进的安全帽佩戴检测系统

## 目标

设计并实现一套可本地部署的安全帽佩戴检测系统，以"人员头部是否佩戴安全帽"为检测对象，
在完成基础目标检测的同时给出违规判定与实时告警，并通过图形界面支持图片、视频、摄像头三种输入。

具体指标目标：

1. 检测精度：mAP@0.5 ≥ 0.85（机器视觉验收常见门槛）；
2. 推理速度：FPS ≥ 15，满足视频实时性要求；
3. 功能完整：检测、计数、跟踪去重、违规告警、结果保存、阈值可调、GPU/CPU 可切换；
4. 工程规范：目录分层、依赖锁定、可复现（固定随机种子与数据划分）、一键启动。

## 系统设计

### 1、系统功能模块架构图

系统分为四层：输入层负责四种数据源的统一接入；检测核心层完成推理、跟踪、违规判定与告警；

#### 2.2 数据集

采用公开数据集 `keremberke/hard-hat-detection`（经 HuggingFace 镜像下载，原始 1.12 GB），
原始规模 19445 张、55391 个标注框，标注为头部级二分类：`hardhat`（戴安全帽的头部）
与 `no-hardhat`（未戴安全帽的头部）。

数据并非直接使用，而是完成了一套二次加工：

| 环节 | 处理 | 结果 |
|---|---|---|
| 格式转换 | COCO 绝对像素坐标 → YOLO 归一化中心点坐标 | 55391 框全部转换 |
| 异常框剔除 | 宽或高 ≤ 1 像素的退化框 | 剔除 2 个 |
| 无标注图处理 | 无任何标注框的图片不纳入 | 排除 301 张 |
| 重复图去重 | 全量 MD5 比对，防止训练/验证同源泄漏 | 剔除 3 张 |
| 分辨率统一 | 长边统一到 640 | 全部 640×640 |
| 数据集划分 | 打乱后按 8:1:1 重新划分（种子 42） | 15552 / 1944 / 1945 |
| 标注校验 | 字段数、类别越界、坐标越界、空标签、孤儿标签、跨集合重复 | 0 个问题 |

最终可用 19441 张、55381 个标注框。类别分布 hardhat 42423（76.6%）、no-hardhat 12958（23.4%）；
**目标尺寸分布中小目标（面积占比 <1%）占 60.1%**，这是后续网络改进的直接依据。

#### 2.3 网络结构改进：增加 P2 小目标检测层

原生 YOLOv8 的检测头接在 P3（80×80）、P4（40×40）、P5（20×20）三个尺度上，最小步长为 8。
本项目数据中 60.1% 的目标是面积占比不足 1% 的小目标（远景工人的头部），映射到 P3 特征图上
往往只剩数个像素，漏检难以避免。

因此本设计在 Neck 中向下延伸一条分支，把 P2（160×160，步长 4）也接入检测头，
构成 P2/P3/P4/P5 四尺度检测：

```yaml
# 新增 P2 分支（对应 yolov8n-p2.yaml 第 16~18 层）
- [-1, 1, nn.Upsample, [None, 2, "nearest"]]   # 16  (160×160)
- [[-1, 2], 1, Concat, [1]]                     # 17  cat backbone P2
- [-1, 3, C2f, [128]]                           # 18  P2 小目标检测层
...
- [[18, 21, 24, 27], 1, Detect, [nc]]           # 28  Detect(P2,P3,P4,P5)
```

代价：参数量由 3.16M 增至 3.35M（+6%），浅层高分辨率特征图带来额外计算量。
收益：小目标的定位与召回显著改善，实测结果见 2.5 节。

#### 2.5 训练结果与消融实验

三组实验使用**同一份数据划分、同一套超参数、相同轮数**，仅网络结构不同：

| 实验 | 结构改动 | 参数量 | P | R | mAP@0.5 | mAP@0.5:0.95 |
|---|---|---|---|---|---|---|
| baseline | 原生 YOLOv8n | 3.16M | 0.9030 | 0.8930 | 0.9354 | 0.5813 |
| +CBAM | SPPF 与 P3/P4/P5 颈部共 4 处插入 CBAM | 3.18M | 0.9093 | 0.8856 | 0.9348 | 0.5769 |
| **+P2（本设计）** | **新增 P2 四尺度检测层** | **3.35M** | 【待填】 | 【待填】 | 【待填】 | 【待填】 |

结论：

1. **CBAM 注意力在本任务上没有收益**，mAP@0.5 反而低 0.06 个点，mAP@0.5:0.95 低 0.44 个点，
   差异处于随机波动范围。原因分析：本任务仅 2 类且"黄色安全帽 vs 裸露头部"特征区分度极高，
   COCO 预训练已充分覆盖此类语义，注意力机制擅长的"抑制复杂背景干扰"在此收益有限。
   该负结果如实保留，作为消融实验完整性的体现。
2. **P2 小目标检测层带来【待填】个点的 mAP@0.5 提升**，与"小目标占 60.1%"的数据分析相互印证，
   说明结构改进是针对数据特性做的，而非盲目堆叠模块。

### 3、源码展示

#### 代码 1：违规检测与告警主逻辑（`src/detect.py`）

```python
def analyze(self, frame: np.ndarray) -> FrameResult:
    """分析一帧图像，返回绘制结果与统计信息。"""
    result = self._infer(frame)          # 跟踪推理（BoT-SORT）
    boxes = result.boxes
    n_ok = n_bad = 0
    violators: list[int] = []
    if boxes is not None and len(boxes) > 0:
        xyxy = boxes.xyxy.cpu().numpy()
        clss = boxes.cls.cpu().numpy().astype(int)
        confs = boxes.conf.cpu().numpy()
        ids = boxes.id.cpu().numpy().astype(int) if boxes.id is not None else [None] * len(clss)
        for box, cid, cf, tid in zip(xyxy, clss, confs, ids):
            if cid == ALARM_CLASS_ID:      # no-hardhat -> 违规
                n_bad += 1
                violators.append(int(tid) if tid is not None else -1)
                self._draw_box(frame, box, COLOR_VIOLATION, f"NO-HARDHAT #{tid}", thickness=3)
            else:
                n_ok += 1
                self._draw_box(frame, box, COLOR_OK, f"hardhat #{tid} {cf:.2f}")
    # 告警带冷却，避免逐帧刷屏
    alarm = False
    if n_bad > 0:
        if self._alarm_cooldown <= 0:
            alarm = True
            self._alarm_cooldown = ALARM_COOLDOWN_FRAMES
        else:
            self._alarm_cooldown -= 1
    else:
        self._alarm_cooldown = 0
    ...
```

#### 代码 2：界面与推理解耦的多线程取帧（`src/ui_app.py`）

```python
def _loop(self) -> None:
    """工作线程：只负责取帧与推理，结果塞进队列。"""
    while self.running.get() and self.cap is not None:
        ok, frame = self.cap.read()
        if not ok:
            self.running.set(False); break
        try:
            res = self.detector.analyze(frame)
        except Exception as exc:      # 单帧异常不中断整段视频
            print(f"[警告] 单帧处理失败: {exc}")
            continue
        if self.writer is not None:
            self.writer.write(res.annotated)
        if self.frame_queue.full():
            self.frame_queue.get_nowait()
        self.frame_queue.put(res)

def _drain(self) -> None:
    """主线程每 15ms 取一次最新结果并刷新界面，保证界面不卡。"""
    try:
        while True:
            res = self.frame_queue.get_nowait()
            self._render(res.annotated)
            self._update_stats(res.counts, res.fps, res.alarm)
    except queue.Empty:
        pass
    if self.running.get():
        self.root.after(15, self._drain)
```

## 六、总结

本项目完成了从数据处理、网络结构改进、模型训练到界面部署的完整链路。
最终模型在独立测试集上达到 mAP@0.5 = 【待填】、推理 【待填】 ms/张（约 【待填】 FPS），
均超过开题设定的指标要求；系统支持图片、视频、摄像头三种输入，具备计数、跟踪去重、
违规告警与结果保存功能，可在消费级显卡上实时运行。

过程中遇到的问题及解决：

1. **标注格式问题**：初期使用 labelImg 时未切换输出格式，默认生成 PascalVOC 的 xml，
   导致标签无法被训练脚本识别、样本全部被丢弃。解决方案：明确标注规范，统一为 YOLO 的
   归一化 txt，并编写校验脚本对字段数、类别越界、坐标越界、空标签、跨集合重复做全量检查。

2. **显存换页导致训练异常缓慢**：batch=32 时显存分配达 6.3 GB，逼近 8 GB 上限，
   Windows 的 WDDM 机制将显存向内存换页，单步耗时从 80 ms 恶化到 2020 ms（吞吐下降 6 倍）。
   解决：通过实测对比 batch 8/16/32 的吞吐与显存曲线，选定 batch=8（P2 结构）与
   batch=16（原生结构），使吞吐恢复到正常水平。

3. **验证阶段内存溢出**：每轮验证时训练的 dataloader 子进程尚未释放，验证又新建同等数量子进程，
   12 个进程同时解码图片导致 16 GB 内存耗尽（OpenCV 分配 1.3 MB 失败），训练中断。
   解决：将进程数由 6 降至 2，并在多任务之间加入等待；同时确认 Ultralytics 续训时会用
   checkpoint 内的 `train_args` 覆盖命令行参数，因此需直接修改 ckpt 而非传参。

4. **注意力机制无增益**：按常规思路引入的 CBAM 注意力经严格消融后发现并无收益。
   本项目的处理是不隐藏该结果，而是分析原因（任务类别少、目标特征区分度高、预训练已充分），
   并转向真正对症的小目标改进（P2 检测层）。这比强行声称"改进有效"更符合实验规范。

不足与改进方向：

1. 数据集为公开数据，缺乏真实作业现场（逆光、夜间、雨雾、粉尘）的样本，
   跨域泛化能力尚未验证；
2. 未引入更大规模的模型对照（如 YOLOv8s+ P2），精度上限未知；
3. 部署侧仅完成 ONNX 导出验证，尚未在嵌入式设备（如 Jetson、树莓派）上实测；
4. 告警目前为画面级提示，后续可对接推送（企业微信/短信）形成完整闭环。
