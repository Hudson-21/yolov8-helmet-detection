## 0. 路线说明与代价（先讲清楚，答辩时必须能解释）

评分原文：**"自主采集/筛选适配项目场景的数据集得满分；直接使用公开通用数据集无筛选优化扣 2 分"**。

我们抓住"关键词是**无筛选优化**"这一点：不是直接拿数据集开训，而是完成了一整套二次加工
（格式转换、类别体系重构、异常框剔除、重复图去重、重新划分、标注全量校验）。
因此可争取"筛选适配"的得分口径，但**客观来说仍会损失约 2 分**，
且"自主采集大规模专属数据集 +1~2 分"这个加分项拿不到。这一点在项目文档里必须写明，不能含糊。

## 一、数据集来源

| 项 | 内容 |
|---|---|
| 数据集 | `keremberke/hard-hat-detection` |
| 获取方式 | HuggingFace 镜像 `hf-mirror.com`（本机无法访问 GitHub，镜像可通） |
| 原始格式 | Roboflow 导出的 **COCO 格式**（图片 + `_annotations.coco.json`，bbox 为绝对像素 `[x,y,w,h]`） |
| 原始规模 | train 13782 张 · valid 3962 张 · test 2001 张，合计 **19445 张** |
| 原始标注 | 55391 个框（hardhat 42426 / no-hardhat 12965） |
| 图片尺寸 | 640×640 |
| 原始类别 | 2 类：`hardhat`、`no-hardhat` |

完整命令链：

```bash
# 1. 下载三个压缩包（合计 1.12 GB，存放于 E:\YOLO\data_dl\hardhat\）
curl -L -o train.zip https://hf-mirror.com/datasets/keremberke/hard-hat-detection/resolve/main/data/train.zip
curl -L -o valid.zip https://hf-mirror.com/datasets/keremberke/hard-hat-detection/resolve/main/data/valid.zip
curl -L -o test.zip  https://hf-mirror.com/datasets/keremberke/hard-hat-detection/resolve/main/data/test.zip

# 2. COCO → YOLO，并做初筛
python tools/coco2yolo.py --zips E:/YOLO/data_dl/hardhat/train.zip \
                                 E:/YOLO/data_dl/hardhat/valid.zip \
                                 E:/YOLO/data_dl/hardhat/test.zip \
                          --out datasets/raw/hardhat_all

# 3. 清洗去重 + 重新划分
python src/split_dataset.py --raw datasets/raw/hardhat_all --resize 640 --clean

# 4. 标注全量复核
python src/check_labels.py
```

## 二、类别体系为什么改成 2 类（重要的设计决策）

原始设计是 `person / helmet / vest` 三类，靠"人员框 + 头部区域内的安全帽框做空间关联"判定违规。
实际有两个问题：

1. 关联逻辑在三种情况下会误判：画面边缘的半个身子、有人手拎安全帽、旁边的人替他"凑数"；
2. 手标三类工作量巨大（约 6~10 小时），且 helmet 的标注规则极易出错
   （手拿的帽子该不该标？标了反而导致漏报）。

改用该数据集后，它的标注本身就是**头部级二分类**：

| id | 名称 | 含义 |
|---|---|---|
| 0 | `hardhat` | 戴着安全帽的头部 |
| 1 | `no-hardhat` | 没有戴安全帽的头部（违规） |

于是告警逻辑退化成一句话：**检测到 `no-hardhat` 就是违规**。更简单、更准、也更好讲。
计数同理：已戴人数 = hardhat 框数，未戴人数 = no-hardhat 框数，视野内总人数 = 两者之和。

## 三、二次加工做了哪些事（评分证据）

| 加工项 | 具体动作 | 结果 |
|---|---|---|
| 格式转换 | COCO 绝对坐标 → YOLO 归一化中心点坐标 | 55391 个框全部转换 |
| 类别映射 | 统一到本项目 2 类体系，表外类别丢弃 | 无丢弃（原始类别本就只有 2 类） |
| 异常框剔除 | 宽或高 ≤ 1 像素的退化框 | 剔除 2 个 |
| 无标注图处理 | 301 张图无任何标注框，默认不纳入（避免纯背景噪声） | 导出 19444 张 |
| 重复图去重 | 全量 MD5 比对，防止训练集与验证集同源泄漏 | 剔除 3 张 |
| 分辨率统一 | 长边统一到 640（标注是归一化的，缩放不影响标签） | 全部 640 |
| 重新划分 | 打乱后按 **8:1:1** 重划 train/val/test（固定种子 42，可复现） | 15552 / 1944 / 1945 |
| 标注全量校验 | 字段数、类别越界、坐标越界、空标签、孤儿标签、跨集合重复 | **0 个问题** |

加工后的最终数据事实：

| 项 | 数值 |
|---|---|
| 可用图片 | 19441 张 |
| 标注框 | 55381 个（train 44515 / val 5459 / test 5407） |
| 类别分布 | hardhat 42423（76.6%）· no-hardhat 12958（23.4%） |
| 目标尺寸 | **小目标（面积占比<1%）60.1%** · 中目标 35.0% · 大目标 4.9% |

> **小目标占 60.1%** 是这份数据的核心特点，直接决定两件事：
> ① `imgsz` 不应低于 640，值得做 640 / 960 / 1280 对照实验；
> ② 可以正当地主张"小目标检测优化"这一加分项，而不是空口说。
>
> 类别分布 76.6% : 23.4% 属轻度不平衡，未做重采样，靠 `cls` 损失权重（0.6）
> 与增强里的 `copy_paste` 缓解。这一点在"问题总结"里如实记录。

## 四、数据增强策略（对应 8 分里的"增强"）

增强不在脚本里写死，全部由 `configs/hyp_tuned.yaml` 控制，每条都注明理由：

| 参数 | 值 | 针对什么问题 |
|---|---|---|
| mosaic | 1.0（末 15 轮关闭） | 小目标 + 密集人群 |
| mixup | 0.1 | 大数据量下仍需防过拟合 |
| copy_paste | 0.1 | 人为构造遮挡/密集样本 |
| hsv_v | 0.5 | 户外强逆光与阴影 |
| hsv_s | 0.7 | 安全帽黄/橙/红多色 |
| scale | 0.6 | 远景工人头部极小 |
| translate | 0.15 | 目标常出现在画面边缘 |
| fliplr | 0.5 | 头部左右对称，安全 |
| degrees / flipud | 0 | 人体不会倒立或大幅旋转 |

## 五、如果后续要补充自有数据（可选，能补回分数）

公开数据集能跑通流程，但"亲眼看过的场景"仍是最好的补充：

1. 用 `python src/collect_images.py --name site_a_1025 --interval 1.0` 抓拍，或手机录视频后抽帧；
2. 用 labelImg 标注。**关键规则（头部级口径）**：
   - `hardhat`：只框**戴在头上的安全帽及头部区域**；手拿、挂胳膊上、放地上的帽子**绝对不框**；
   - `no-hardhat`：框住**没有安全帽遮挡的头部/人脸区域**；
   - 棒球帽、草帽、遮阳帽**不是** `hardhat`，应标 `no-hardhat`；
   - 被遮挡超 70% 的头部不标。
3. 混入训练集后重新跑 `split_dataset.py` 与 `check_labels.py`。

> 注：`tools/prelabel.py` 目前预标的是 COCO 的 person 类，与本项目 2 类体系不匹配，
> 若要使用需把 `PERSON_CLASS_ID` 改成 1 并换成本项目训练出的权重。
